files in `dist/`, and that is as far as the verification goes.

Three things `ARCHITECTURE.md` requires are still missing from it or the code:

- **The CloudWatch billing alarm §6 requires for Bedrock cost runaway does not exist.**
  No alarm is declared. `MAX_TOKENS = 80` and `TEMPERATURE = 0.2` are in place, so the
  token-cost lever is set; detection is not.
- **The 90-day TTL on the events table is unreconciled.** The TTL attribute is declared
  but only idempotency rows and connection rows populate `expires_at`, so event items
  are retained indefinitely.
- **The events table is now read, but only by a single-homeowner key.** `GET /events/today`
  queries the `date` partition, so the partition finally has a reader. There is no
  per-account separation anywhere: one table, one static `X-Query-Key`, one homeowner. That
  is a deployment blocker for anything multi-user, recorded as D022.

The 1-hour pre-signed URL that §6 requires **is** implemented, in the delivery path
rather than a query path: `src/lib/overlayPush.ts` signs each snapshot key with
`PRESIGNED_URL_TTL_SECONDS = 3600` and sends the signed URL in the §3.4 payload. What
is still absent is any read path that would need to sign on the owner's behalf.

`.env.example`, `package.json`, `src/lib/signatureVerifier.ts`, and
`src/lib/dynamoClient.ts` were on this list until their phases created them; the
contract's self-invalidating declarations flagged each the moment it appeared, which is
how this table stayed correct instead of going stale.

**The chain now reaches the wire, and the events are readable.** Ingress → queue →
snapshot → Bedrock → WebSocket is wired and tested against fakes, and
`GET /events/today` returns a day's events with pre-signed snapshot URLs. Every backend
stage `ARCHITECTURE.md` plans is now written except the daily summary.

It still stops short of a screen. There is **no Fire TV or web front end**, and the
picture-in-picture `ARCHITECTURE.md` §3.4 specifies is not implementable on Vega OS at
all — decision D021 records why. `description_source` on each event distinguishes a
model-written sentence from an FR11 fallback.

No event has ever been produced by a live Ring delivery, and the FR6 8-second target is
unmeasured across three queue hops.
